# 用 AI Passport 模拟 soundcore Work(安克 AI 录音豆 D3200)

本固件把 FoloToy AI Passport 模拟成一颗 **soundcore Work**(安克 AI 录音豆,产品码
**D3200**)。为真机编写的手机 App——例如 [Soundcore Manager](https://github.com/tacshi/Soundcore),
其逆向协议文档就是本项目的规格——可以通过 BLE 发现并连接 AI Passport,像使用原机一样:
读取设备信息、同步时钟、建立加密会话、开始/暂停录音、实时音频流转写、离线下载文件、
Wi‑Fi 批量导出、绑定与恢复出厂。

## 功能

- **以 D3200 身份广播**:32 位服务 UUID `0x020CF5DA`(`020cf5da-0000-1000-8000-00805f9b34fb`),
  厂商数据含 MAC、绑定标志位与 `soundc` 标记,设备名 `soundcore Work`。
- **GATT**:写特征 `0x7777`,通知特征 `0x8888`。命令统一为 `08 EE …` 帧,应答统一为
  `09 FF …` 帧(累加校验和);应答按 MTU 拆分成多个通知。
- **用自带麦克风录音**:16 kHz 单声道 Opus,20 ms SILK 帧(16 kbps),存于 4.9 MB 的
  LittleFS 分区(约 40 分钟)。每帧装进协议固定的 160 字节单元。
- **与原机一致的加密**:ECDH P-256 握手(`2E 01`),HKDF-SHA256 派生会话密钥;每条录音
  一个随机 AES-256 密钥,包裹后放在文件头里下发;每个 160 字节单元做 AES-CTR。未握手时
  发送短文件头与明文单元,客户端同样接受。
- **实时传输**:录音开始(App 或按键)时设备推送 `18 82` 与 `1A 06 <fileId>`;App 的实时
  请求(`1A 07`,realtimeFlag 1)随即收到正在编码的帧,支持从任意字节偏移续传。
- **Wi‑Fi 快速导出**:`1A 05` 用 App 指定的 SSID/密码开启热点,应答 `192.168.4.1:443`,
  无线从 BLE 切换到 Wi‑Fi,提供 `wss://` WebSocket 传输(十六进制文本请求,二进制
  `1A 07/08/0A` 帧)。TLS 证书是设备首次使用时生成的自签名 P-256 证书,缓存在 NVS;
  仓库中不保存任何私钥。收到 `FINISH`、超时或长按 OK 后恢复 BLE 广播。

## 协议覆盖

| 命令 | 行为 |
| --- | --- |
| `01 01` 设备信息 | 电量档、固件、序列号、存储 KB、录音状态、Wi‑Fi 固件 |
| `01 A6` 同步时间 | 设置时钟与时区;之后的新录音以真实 Unix 时间戳作 ID |
| `01 B8` 恢复出厂 | 应答后清空录音与设置并重启 |
| `01 03` 推送 | 连接期间电量档变化时推送 |
| `18 82` 录音 | `01` 开始/继续,`02` 暂停;应答当前状态(`00` 停止时附带时长) |
| `1A 0E` / `1B 0E` 列表 | 每页 10 条(`1B` 带结束时间),附当前录音 ID 与时长 |
| `1A 07` 传输 | 离线下载或从偏移开始的实时流:文件头、`1A 08` 分片、`1A 0A` 完成 |
| `1A 10` 删除 | 删除已结束的录音 |
| `1A 0F` / `1A 11` | 确认即可(无经典蓝牙,数据始终走 BLE) |
| `1A 05` / `1A 02` | Wi‑Fi 热点导出 / 关闭(App 没有停止命令,暂停中的录音会先保存) |
| `0B 87` 绑定/解绑 | 持久化绑定标志(同时反映到广播);绑定后发 `0B 88` 确认 |
| `10 A2` 查找 | 保存并确认 |
| `2E 01` 加密 | 上述 ECDH 握手 |

未模拟:OTA(`01 BB` 返回失败)、设备日志命令(`FF xx`)、充电盒(盒子字段沿用本机数据)、
充电检测(本板无此信号)。

## 使用

1. 烧录本固件,打开为 soundcore Work 编写的手机 App。
2. 扫描:设备显示为 **soundcore Work**。连接后屏幕顶栏变绿,加密握手完成后 **SECURE** 亮起。
3. 在 App 里开始录音,或按设备上的 **OK**。App 对实时流转写;**BOUND**、**SECURE**、
   **LIVE** 显示连接状态。
4. 录音出现在 App 列表中。可通过 BLE 下载,也可选择 Wi‑Fi 导出,按 App 提示加入设备屏幕
   上显示的网络。

| 按键 | 动作 |
| --- | --- |
| OK 单击 | 开始、暂停或继续录音 |
| OK 长按 | 结束并保存录音;Wi‑Fi 导出中则关闭热点 |
| UP / DOWN 单击 | 录音 → 录音列表 → 设备信息 |

一分钟无操作屏幕调暗;此后的第一次按键只点亮屏幕。

## 界面

- **录音页**:顶栏显示连接状态与电量;圆环在录音时随麦克风电平变化(红),暂停时满圈
  (琥珀色);中间是计时、当前文件或传输进度,下方是状态标签与存储占用。
- **录音列表**:最新 8 条录音的日期、时间与时长。
- **设备信息**:模拟型号、MAC、序列号、固件、绑定/会话/时钟状态、存储与空闲堆。
- **Wi‑Fi 导出页**(自动出现):要加入的网络名与密码、服务地址、连接状态与已导出文件数。

## 实现结构

| 文件 | 作用 |
| --- | --- |
| `main/sc_proto.*` | 帧编解码、命令重组、应答载荷(纯 C,host 测试) |
| `main/sc_crypto.*` | ECDH、HKDF、AES-CTR 密钥包裹与单元加密(mbedtls) |
| `main/sc_xfer.*` | 传输文件头、加密分片与完成帧 |
| `main/sc_ring.*` | 实时传输用的最近帧环形缓冲(纯 C,host 测试) |
| `main/sc_store.*` | LittleFS 录音文件:每文件密钥、定位索引、断电恢复 |
| `main/sc_audio.*` | ES8311 采集与 Opus 编码任务 |
| `main/sc_ble.*` | NimBLE 广播、GATT 与通知发送 |
| `main/sc_wifi.*` | SoftAP、HTTPS/WebSocket 服务、设备端证书 |
| `main/sc_core.*` | 命令分发、录音状态机、BLE 传输任务、Wi‑Fi 生命周期 |
| `main/sc_ui.*` | LVGL 界面 |

`partitions.csv` 为 3 MB factory 应用分区 + 4.9 MB `storage` 分区。烧录合并镜像时分区内容
是否保留,见[烧录与数据策略](docs/development/engineering/firmware-layout.zh_CN.md#烧录与已存数据)。

## 验证情况

- Host 测试:`tests/test_sc_proto.c` 与 `tests/test_sc_ring.c` 按客户端解析偏移校验帧布局,
  并检查环形缓冲不变量。`tests/test_sc_client_compat.py` 把固件的协议与加密代码编译到主机,
  与客户端逻辑的 Python 移植互相校验:ECDH 共享密钥、HKDF、文件密钥解包、逐单元解密、
  按 BLE 分片重组以及命令解析。主机缺少 mbedtls 或 `cryptography` 时跳过。
- 固件可构建,合并镜像通过 `tools/verify_firmware.py`。
- 真机上用 Mac 通过 BLE 扮演 App(客户端逻辑的 Python 移植)验证了:广播与扫描响应、
  连接(MTU 247、数据长度 251、2M PHY)、设备信息、同步时间、ECDH 握手(设备端约 0.3 s)、
  开始/暂停、`1A 06` 推送、加密实时流 50 帧/秒无缺帧(每帧解密后都是 SILK-WB Opus 包)、
  离线下载、文件列表、未结束录音的断电恢复,以及 `1A 05` 应答、切到热点、无人加入超时后回到 BLE。
- **尚未验证**:手机上的 Soundcore App、有客户端加入时的 Wi‑Fi 导出(TLS 握手与传输)、
  麦克风实际音质。

真机实测:BLE 运行时内部空闲堆约 24 KB(实时传输期间最低 20 KB),Opus 任务栈余量约 3 KB。
1M PHY 下 Mac 链路只有 5–8 KB/s,低于实时流需要的 8.3 KB/s,部分连接会卡顿数秒;
请求 2M PHY 后,连续 7 次 25 秒实时流均无卡顿(最高 16 KB/s)。

请仅在自己拥有的硬件上、出于互通目的使用。soundcore 与 Anker 是其各自所有者的商标;
本项目与它们无关。
